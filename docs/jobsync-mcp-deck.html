Foundation

What is the Model Context Protocol?

Open Standard

MCP is an open protocol (by Anthropic) that lets LLMs call external tools, read resources, and use structured prompts — across any client that implements the spec.

Client ↔ Server Model

Your MCP client (Claude Code, Claude Desktop, Cursor) connects to an MCP server (like JobSync). The server declares tools; the LLM decides when to call them.

Model-Agnostic

The server never imports the Anthropic SDK. Any model that speaks MCP can drive the workflow — swap clients freely.

Three MCP Primitives

  • Tools — callable functions with typed inputs / outputs
  • Resources — readable data sources (files, DB, API)
  • Prompts — reusable workflow templates the LLM can invoke

JobSync uses all three: 22+ tools, ~/.jobsync/ file resources, and pre-built workflow prompts like scrape_jobs_workflow.

Tool Category 1

ATS Fast-Path Fetchers

Pull job postings directly from Applicant Tracking System public APIs — bypassing web scraping entirely. Disabled by default; set enableFastPath: true in config.

Greenhouse

fetch_greenhouse_jobs

Calls boards-api.greenhouse.io public JSON endpoint. Pass a company slug like "stripe". Supports batch slugs in one call.

Lever

fetch_lever_jobs

Calls api.lever.co/v0/postings. Slug is the Lever board identifier, e.g. "netflix" for jobs.lever.co/netflix.

Ashby

fetch_ashby_jobs

Calls api.ashbyhq.com/posting-api/job-board. Slug e.g. "anthropic". Returns structured postings with all available metadata.

Why this matters: Web search indexes lag by hours. Fast-path fetchers hit the ATS JSON API directly — you get real-time postings at scale without relying on the LLM's web search quota.

Tool Category 2

Filter & Classification Tools

filter_us_location

Deterministically decides if a location string is non-US. Returns { likelyNonUS: boolean }. Used before every upsert when US-only mode is active.

filter_title_keywords

Cheap pre-filter: rejects excluded seniority keywords (Senior, Staff, Principal…) and requires at least one include keyword. Defaults tuned for new-grad tech roles.

detect_industry_tags

Given company + title, returns: industry (22-category taxonomy), tags (FAANG+, Quant, YC, Unicorn…), H1B sponsor flag, and job board source.

classify_job_batch

The power tool — runs all three classifiers over an entire array in one call. Returns a parallel verdicts array with passes, industry, tags, h1bSponsor. Minimises LLM round-trips.

Tool Category 4

SQLite Dedup Cache Tools

Read

cache_is_seen

Check if a job (by URL or composite key) has already been synced. Returns { seen: boolean }. Called before every upsert to avoid duplicates.

Step 1 of 2 in dedup loop

Write

cache_mark_seen

Stamp a job as processed after a successful upsert. Persists to ~/.jobsync/cache.db (SQLite). Survives process restarts.

Step 2 of 2 in dedup loop

Maintenance

cache_prune

Delete cache entries older than N days. Keeps the SQLite file lean. Recommended to run periodically or as part of a cron workflow.

Run monthly or on schedule

Why SQLite (not in-memory)?

Each MCP tool call is stateless — the server can be restarted between runs. SQLite on disk ensures dedup state persists across sessions, cron runs, and server restarts without requiring a separate database service.

Profile I/O Tools

Used during onboard to bootstrap profile

Parse

profile_parse_resume

Parse a plain-text resume into structured profile sections. Called once during jobsync-mcp onboard to bootstrap the profile directory.

One-time setup — run with onboard command

Tool Category 6 & 7

Link Verification & Date Tools

Link Verification

verify_job_link

HEAD-request a job apply URL to confirm it still returns 200. Returns { live: boolean, statusCode }. Prevents syncing dead listings.

verify_job_link_batch

Same check over a batch of URLs in parallel. Returns per-URL verdicts. Run after classify and before upsert for a clean pipeline.

Ashby Date Tools

ashby_get_date_posted

Fetch the publishedAt date for a single Ashby posting via their detail API. Ashby's list endpoint returns null for datePosted — this fills the gap.

ashby_get_date_posted_batch

Batch version — resolve dates for up to N Ashby postings in parallel. Falls back to stamping today's date if the API is unreachable.

Known quirk: Ashby's listing API always returns null for datePosted. The date tools call the individual posting endpoint to retrieve the real publishedAt timestamp before upserting to Airtable.

Tool Category 8 & 9

Markdown Sink & Utility Tools

Sink

markdown_append_jobs

Append jobs as a formatted Markdown table to ~/.jobsync/jobs.md. No Airtable account needed. Great for quick audits, offline viewing, or Git-tracked job logs.

# jobs.md output | Title | Company | Date | Link | | SWE II | Stripe | 2026-04-17 | ... |
Utility

jobsync_ping

Sanity-check tool. Returns { pong: true, version, latestVersion, updateAvailable }. Always the first call in any workflow — verifies the server is connected and running the latest version.

Auto-update Check

Ping hits registry.npmjs.org/jobsync-mcp/latest and compares semver. If updateAvailable: true the LLM notifies you to run npm i -g jobsync-mcp@latest before proceeding.

Getting Started

Install & Configure

# 1. Install globally
npm i -g jobsync-mcp
 
# 2. Run setup wizard (sink, keys, options)
jobsync-mcp init
 
# 3. Parse your resume into a profile
jobsync-mcp onboard --resume /path/to/resume.pdf
# Register with Claude Code (user-scoped)
claude mcp add --scope user jobsync jobsync-mcp
 
claude mcp list
# → jobsync: ✓ Connected

Claude Desktop / Cursor

jobsync-mcp print-client-config
 
# Paste output into:
# macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
# Win: %APPDATA%\Claude\claude_desktop_config.json
# Cursor: ~/.cursor/mcp.json

MCP Prompts

Running Workflows

One-Time

/mcp__jobsync__onboard_profile

Reads raw-resume.txt, writes skills.md / experience.md / projects.md, detects and proposes roles. Confirm to save roles.json.

Primary Workflow

/mcp__jobsync__scrape_jobs_workflow

Full pipeline: ping → profile_read → search → classify → dedup → upsert. Optional args:

companies=Anthropic,Stripe roleKeywordsOverride=SDE lookbackHours=48

As a Cron Job

# Windows Task Scheduler / Unix cron claude -p "invoke scrape_jobs_workflow from jobsync with lookbackHours=24"

Set it to fire every morning — wake up to a fresh Airtable of new postings matching your profile.

Tips for Best Results

  • Run onboard once before your first workflow
  • Enable enableFastPath for real-time ATS data
  • Set lookbackHours: 24 for daily cron runs
  • Use cache_prune monthly to keep DB lean
